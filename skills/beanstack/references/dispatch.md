# 派工

模型看 `model-roster.md`，外部 CLI 看 `external-cli.md`。

## 何时派

- 派：独立可并行的单元、会挤占主上下文的大量读取、需要新视角的复核验证。协调器自己做：依赖链步骤、同文件连续修改、20 次调用内能做完的事（主上下文超过 20 万时 10 次），以及裁决、收货、改规则。
- 派几路按问题定；侦察可同题两路互证，综合者逐条核实，不按票数。
- 探索只做一次：协调器读过代码就把 `文件:行`、已排除方向、验收命令写进任务书；没读过就先派侦察出清单，或让执行者自己探索到实现。不派冷启动子代理只拿目标并行改代码。
- 预计超过 150 次调用就拆段；返工按下文默认新派。
- 执行者卡在关键决策时停下报告；协调器也拿不准就做一次「顾问问询」。

## 多路形态

| 形态 | 什么时候 | 怎么做 |
|---|---|---|
| 多候选 | 没有先例的设计、一次尝试容易锁死形状的方案或文案 | 同一题面派 2–3 路（尽量跨厂），各自独立产出并写明考虑过、否掉了什么；先定 3–6 条可打分的判据，由非作者、非同厂的一路按判据打分选底，再把其它候选的长处嫁接进来，最后验证 |
| 分片 | 覆盖类工作（每个包、每条路由、每个调用点一路） | 每路题面自包含，写清分片、怎么验证、交什么；回报只用「通过 / 有问题 / 受阻」并附证据，能证明的问题全部列出；漏记提交号或方法的结果重派一次，再缺记为缺口，缺口不算通过 |
| 竞速 | 同题多路看谁先做对，或比较模型 | 派之前声明取舍规则（先过者、全部排名、取最好）；测量类题面写明提交号、样本数、顺序 |
| 对抗复核 | 高风险 diff 或设计 | 多个异厂复核者各自尝试攻破，只留用真实命令跑出来的 finding，协调器逐条重跑确认；同根因合并 |

掉线一路就按 N-1 继续并写明。汇总时不粘贴原始输出。

## 任务书

开头用 `prompt-preamble.md` 和项目条款，再写：目标与非目标、依据、入口与写入范围、验收（判据与命令，UI 写到状态级）、真正需要裁决的停止条件。子代理看不到父会话。派 Codex 做浏览器探针时写明一律无头。

- **验证位**：给用户原话（逐字、最前）、附图、核对表、被验证与对照提交、启动方式、入口、账号；不给实现者的说明和设计取舍。同一条三轮不通过就报告用户。
- **设计稿先行**：使用 Claude 宿主做新页面或整页改版时，优先用 **Claude Design** 出交互与视觉原型并定稿，再按「还原布局、构图与交互，颜色/字号/间距/圆角一律走项目 `DESIGN.md` token」翻译成实现任务书，防止设计漂移。其余宿主或局部多方案由协调器建稿（多方案放一份稿）；设计位写简报、按规范审查、把选定稿翻译成任务书。稿偏离规范时改稿；用户要新方向时可有一个方案跳出规范并标明偏离点。
- **外部检索**：题面只给症状、环境、约束、已排除方向；要求 800 字内中文，每条写候选｜置信度｜来源 URL｜适用性，找不到来源就直说。

## 调度模式

由用户指定，没说用默认，生效到改口；协调器不探测额度、不自行切换。默认：原生子代理按角色执行，外部通道只做异系复核和检索。均衡：GPT 分担 Claude 负载。省 Claude：Claude 只做协调器，侦察仍可用。具体分工看路由表。

- 回合注入的「GPT fast｜Grok fast｜Astra｜Gemini」开关决定模型 ID 与 `--fast`。项目没有注入这些开关时，以用户在对话里的明确说法为准，没说的一律按关闭处理（Grok 例外，默认 fast）。
- 派外部通道前用 `scripts/channels.sh` 看本机装了哪些 CLI。路由表点到的通道没装或启动失败，按 roster 优先级换下一个候选；都不可用就回落到同一角色的 Claude 原生子代理，交付「模型使用」里写明。只有 Claude 原生子代理时，三种模式都等于默认模式。
- 用户说「只用 X 和 Y」时覆盖路由表；没有异系就写「未做异系复核（用户限定通道）」。
- 本机协调器可经 `cloud` 通道把整包测试、视觉检查、路径验证派到云端；Git、收货、异系复核留本机。
- 收货标准不因模式降低；高风险实现交外部模型时协调器亲自读 diff 并实测。

## 额度耗尽

- `reason=quota`：按 roster 优先级换通道（省 Claude：GPT → Grok；均衡：后端 → Grok，前端精准执行 → Gemini；其余停在协调器）。只看错误文本判定。
- `reason=capacity` 或断网：同通道退避重试一次再换；Codex 优先 `codex exec resume`。
- 换通道只对那一次有效，下次先探测首选通道。

## 原生子代理

- 调用时可覆盖 `model`、`effort`；`description` 末尾写「· 模型/档位」。广度搜索用侦察定义，不用内置 Explore。子代理缓存 5 分钟，长验证交协调器跑。
- 并行写入默认同一 worktree 分区；要改同一文件、独立跑测试或 dev server、试两套方案时用 `isolation: "worktree"`：派前先提交，任务书写基准 SHA，依赖离线安装（不软链主检出），合回后 `git worktree remove` 与 `git branch -d`，冻结前 `git worktree list` 核对。
- 返工默认新派，带原任务书、之后的全部指示、上一轮报告和分支（续的代理容易被自己之前的思路锚住）；只有要用它的未提交改动、正在跑的进程，或缓存未过期且返工很小时才用 `SendMessage` 续。
- 外部 CLI 用 `--wait` 放进后台命令，描述写「<任务> · <模型>/<档位>」。
- 主会话阶段之间 `/compact`，一个分支一个会话；授权与门禁结论写进 tasks，不只留在摘要。

## 其它

- Codex 做协调器：用 Codex 侧角色定义，传 roster「Codex 内置子代理」一行的模型档位；异系复核读作 Claude。
- dynamic workflow 只在用户点名或几百文件级任务时用，每阶段指定模型。
