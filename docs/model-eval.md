# 模型评测摘要与实测明细

BeanStack 派工清单（`skills/beanstack/references/model-roster.md`）每一行的依据。数据来自我们在真实生产仓库（豆老板 Bean Boss）上做的 6 轮评测，时间跨度为 2026-10 至 2026-11。所有数字均标明口径，不凭印象拍脑袋。

> **先说局限**：多数组合每题跑 1 次，属于筛选性质，用来定派工方向，不是学术榜单。题目切自真实业务仓库，对你的项目仅作先验参考。UI 审美结论一律以人工画廊盲评为准，机评模型评委只作参考（异厂评委会偏向自家体系，两位评委一致的只有三对）。

## 一、方法与题集

- **题集来源**：全部从真实仓库切出，带硬判据的题均经过 `verify-card` 验证（基线上必红，参考实现转绿）。原 10 题里的 `FE-1`、`REV-1` 及第二批 6 道新执行题为 held-out（任务书冻结，不用于调题）。
  - **原 10 题（实现 + 只读）**：
    - `3D-1`（3D 相机与像素比）
    - `MO-1`（动效组件、reduced-motion 与打断行为）
    - `FE-1`（设备卡片组件与设计 token 约束）
    - `HTML-1`（单页静态实现与可访问性）
    - `BE-1`（并发排队状态机）
    - `PAY-1`（支付退款卡单修复）
    - `REV-1`（资金 diff 中埋入 5 处缺陷审查）
    - `VIS-1`（界面截图找茬 8 处）
    - `LONG-1`（10 万 token 长文 12 问）
    - `COPY-1`（用户公告中文文案）
  - **第二批 6 道新执行题**：退款并发对账、门禁链状态机、带测试陷阱的超时清理、设计 token 落地、合集条加载态、业务上限规则。
  - **路径验证位 13 张卡**：10 张埋入真实缺陷的用户路径卡 + 3 张无缺陷对照卡（准入门槛：命中 ≥ 7/10、误报 ≤ 1/3）。
- **运行方式**：每次运行均为独立无头 CLI 会话，等价于协调器派出的一个子代理；耗时为真实墙钟（wall-clock），费用与 token 取自 CLI 自身统计。
- **总规模**：合计约 **40 道题、400+ 次独立运行**，覆盖 Claude、GPT、Grok、Gemini 四家 20 余个「模型 × 思考档位」组合。

## 六、另外三条改变工作流设计的关键发现

1. **思考档位存在明显拐点**：Opus high 比 medium 贵约五成却没变快、分数也没稳定涨；Opus low 并发题挂掉且性价比不如 Sonnet high；Haiku max 贵 5–30 倍还会过度探索破坏格式。**低于拐点返工吃掉省的钱，高于拐点等待和额度翻倍、收益近零。**
2. **长任务里 Sonnet 并没有想象中省**：真实长会话统计显示，Sonnet 5.5 与 Opus 5.5 的缓存读取单价相同，而长任务大头正是缓存读取（单会话执行子代理各自读取约 3460 万缓存 token），总价只便宜约四成——多返工一次就反超。因此按「一次做对」派工，拿不准就直接派 Opus medium。
3. **慢不在模型生成，而在等待与全量重活**：一轮 9.5 小时真实会话里，执行子代理墙钟是模型生成耗时的 **4–5 倍**，时间耗在跑命令、全量测试抢 CPU 和后台无人收货。这直接催生了「开发期只跑受影响测试 + 独立验证位定点取证 + 后台结束立刻收货 + 钩子拦截手写 sleep 轮询」的整套机制。
